Партнёр передаёт анкету один раз. Ping3 приводит её к формату каждого кредитора и отдельно получает статусы выдачи.

Форматы анкет у кредиторов

У каждого кредитора свой формат анкеты и свой способ сообщить о решении. Партнёру приходится учитывать эти различия, даже если в его интерфейсе клиент заполняет одну анкету.

Единый API для партнёров

Я запустил Ping3 с единым API для партнёров. Платформа преобразует анкету под требования кредитора и возвращает одобренные предложения в общем формате. Партнёр показывает их клиенту в своём интерфейсе. О фактической выдаче кредитор сообщает отдельно.

Как партнёр узнаёт о выдаче займа?

Сначала кредитор возвращает предложение. Когда клиент оформит заём, кредитор отправит отдельное сообщение о выдаче. По этому событию платформа может связать выданный заём с исходной заявкой.

Платежи в MVP Group

По итогам A/B-теста выбрал платёжного провайдера. Затем доработал эквайринг, обработку токенов и привязку карт. За шесть месяцев доля платящих среди пользователей с привязанной картой выросла с 2,1% до 5,4%, на 3,3 процентного пункта.

Ранжирование предложений в MVP Group

Настроил, обучил и внедрил CatBoost, чтобы упорядочивать предложения кредиторов. AUC модели превысил 0,90. Три месяца дорабатывал модель и переобучал её с учётом сезонности. Решение по каждой заявке принимает кредитор.

Когда ещё один кредитор добавляет выдачи

Где смотреть эффект

Я бы считал долю уникальных заявок, по которым в одинаковый срок пришло подтверждение хотя бы одной выдачи. Одна анкета может породить несколько запросов и предложений. Связка по идентификатору исходной заявки позволяет учесть каждую заявку один раз и увидеть, у какого кредитора её одобрили и выдали заём.

Как проверить вклад кредитора

Для заявок, подходящих новому кредитору, я бы сравнил случайно распределённые группы со старым набором кредиторов и с расширенным. Если доля заявок с выдачей устойчиво выше в группе с новым кредитором, интеграция добавляет выдачи. Если меняется только распределение выдач между кредиторами, стоит взвесить затраты на поддержку. В обеих группах проверил бы время до первого предложения и полноту статусов выдачи.
