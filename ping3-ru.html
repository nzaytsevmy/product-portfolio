Одна анкета, несколько предложений

Единый API для разных форматов

Чтобы показывать предложения разных кредиторов в своём интерфейсе, партнёру нужны данные от каждого. Каждый кредитор запрашивал данные в своём формате и по-своему сообщал результат. При прямых интеграциях партнёру пришлось бы отдельно поддерживать эти различия.

В Ping3 эту работу взяла на себя платформа. У партнёра один формат анкеты и один формат предложения. Ping3 преобразует заявку для каждого подходящего кредитора и приводит ответы к общему виду. Добавление кредитора требует работы на стороне Ping3. Партнёр продолжает пользоваться тем же API.

Четыре события в пути заявки

Условный пример. Клиент отправил анкету у партнёра. Кредитор А вернул предложение. У кредитора Б заявка ещё в работе. Клиент выбрал предложение А, а позже от А пришло подтверждение выдачи.

  1. ПартнёрОтправляет одну анкету
  2. Ping3Готовит отдельные запросы
  3. КредиторыРассматривают заявки
  4. ПартнёрПолучает предложения и статус выдачи
  1. 01Заявка принята

    Ping3 принимает анкету через партнёрский API. Результаты запросов можно связать с исходной анкетой.

  2. 02Запросы отправлены

    Для каждого подходящего кредитора Ping3 отправляет данные в его формате. Кредиторы рассматривают заявки у себя.

  3. 03Пришло предложение

    Кредитор А готов предложить заём. Ping3 передаёт предложение в общем формате. Клиент может открыть его у партнёра.

  4. 04Выдача подтверждена

    Когда клиент оформляет заём и получает деньги, кредитор отправляет отдельный статус. Он связан с исходной анкетой.

Предложение и выдача

Для партнёра у этих событий разная ценность. Предложение даёт клиенту выбор. Подтверждение выдачи отвечает на вопрос, получил ли он деньги. Если считать оба события как одну конверсию, маршрут с большим числом предложений может выглядеть успешнее, даже если выдач столько же.

Как я бы проверял гипотезу

Тест на вклад нового кредитора

Метрика

Для решения о подключении ещё одного кредитора я бы взял долю анкет, по которым подтверждена хотя бы одна выдача за одинаковый период наблюдения. Одна анкета с несколькими предложениями считается один раз.

Тест

В тесте сравнил бы случайные группы подходящих анкет. Первая группа идёт в текущую сеть, вторая — в ту же сеть с новым кредитором. Если доля анкет с выдачей вырастет, это аргумент за расширение. Если изменится лишь доля выдач каждого кредитора, решение зависит от стоимости интеграции и поддержки.

Дополнительно проверил бы время до первого предложения и полноту статусов выдачи. Если новый кредитор сообщает о выдаче с задержкой, часть эффекта может стать видна только после более длинного окна наблюдения.
